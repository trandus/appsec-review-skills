### 1. Authenticated users can hide other users' recognitions by ID
- Category: A01 — Broken Access Control
- Severity: medium
- Exploitability: requires-auth
- Confidence: confirmed
- Location: Grati.Web/Controllers/ProfileController.cs:601-608 (HideRecognition); Grati.Web/Grains/RecognitionGrainAdapter.cs:40-44 (Hide)
- Issue: `HideRecognition` accepts any recognition GUID, loads that recognition directly, and calls `Hide` before reading the current user. `RecognitionGrainAdapter.Hide` persists the hidden state without checking that the recognition belongs to the authenticated user.
- Fix: Load the recognition first and require `recognition.RecipientUserId == currentUserId` before hiding, or expose a repository/grain method such as `HideForRecipient(RecognitionIdentity id, UserIdentity recipientId, ZonedDateTime at)` that performs the ownership check atomically.

### 2. Private tip destinations are exposed through the anonymous recognition flow
- Category: A01 — Broken Access Control
- Severity: medium
- Exploitability: trivial
- Confidence: confirmed
- Location: Grati.Web/Services/RecognitionFlow/RecognitionFlowViewService.cs:37-52 (GetForm); Grati.Web/Controllers/RecognitionFlowController.cs:237-246 (ResolveTipSelection); Grati.Web/Services/Common/TipLinkBuilder.cs:23-28 (BuildOutboundUrl)
- Issue: `GetForm` builds the anonymous recognition form from every `profile.TipDestinations` entry and does not filter `IsPublic`. A visitor can select a private destination and trigger `BuildOutboundUrl`, which sends the browser to the payment URL for that private handle.
- Fix: Filter recognition-flow tip destinations with `.Where(destination => destination.IsPublic)` before constructing `TipDestinationOptionViewModel`, and add a regression test where a private destination is not rendered or accepted by POST.

### 3. Internal doctor endpoint is anonymously accessible and discloses environment diagnostics
- Category: A05 — Security Misconfiguration
- Severity: medium
- Exploitability: trivial
- Confidence: confirmed
- Location: Grati.Web/Controllers/InternalDoctorController.cs:8-24 (Get); Grati.Web/Diagnostics/EntraConfigurationDoctorCheck.cs:23-42; Grati.Web/Diagnostics/SqlConnectivityDoctorCheck.cs:19-49; Grati.Web/Diagnostics/BlobStorageDoctorCheck.cs:27-49; Grati.Web/Diagnostics/SecretDiagnosticValue.cs:6-19
- Issue: `/internal/doctor` is marked `[AllowAnonymous]` and returns diagnostic metadata for SQL, Blob Storage, Entra, and time checks. The payload includes service hosts, callback paths, exception classes, and secret length/fingerprint metadata for configured secrets and connection strings.
- Fix: Require authorization for `InternalDoctorController` and restrict it to an admin/operator policy, or bind the endpoint only to an internal network path and remove secret length/fingerprint values from the JSON response.

### 4. Production logging captures user profile, recognition message, and tip-handle data at Debug level
- Category: A09 — Logging & Monitoring
- Severity: medium
- Exploitability: requires-specific-conditions
- Confidence: confirmed
- Location: Grati.Web/Configuration/ServiceCollectionExtensions.cs:158-171 (AddSerilog); Grati.Web/Controllers/RecognitionFlowController.cs:157-165; Grati.Web/Controllers/ProfileController.cs:106-113,245-252,342-346,735-739
- Issue: Serilog is configured with `MinimumLevel.Debug()` for all environments and writes to Seq. Debug logs include submitted recognition messages/customer display names, profile names/roles/bios/photo URLs, and tip handles, so routine production traffic can place PII and payout identifiers into centralized logs.
- Fix: Set the production default level to `Information` or higher and remove raw message, bio, photo URL, and tip handle values from log templates; log only stable identifiers and validation/error categories.

### 5. Dev deployment sends logs to Seq over plaintext HTTP while certificate bypass support is enabled
- Category: A02 — Cryptographic Failures
- Severity: low
- Exploitability: requires-specific-conditions
- Confidence: confirmed
- Location: Infrastructure/Grati.Infrastructure.Azure/Pulumi.dev.yaml:21-25; Grati.Web/Configuration/ServiceCollectionExtensions.cs:168-171,210-216
- Issue: The deployed dev web app is configured as `Production` but sends Seq logs to `http://20.117.48.74:5341`, and the application contains an `IgnoreCertificateErrors` path that disables TLS certificate validation when enabled. If that logging channel carries the PII described above, anyone on the network path can observe or alter log traffic.
- Fix: Use an HTTPS Seq endpoint with valid certificates and set `ignoreCertificateErrors: false`; remove the certificate-bypass branch outside local-only development configuration.
